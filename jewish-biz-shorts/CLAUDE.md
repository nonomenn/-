# ユダヤ・ビジネス系 ショート切り抜きプロジェクト

自分のYouTubeチャンネルの本編動画から、ノウハウ部分を切り抜いて縦型ショート(40〜50秒)を作る。

## 依頼を受けたときの流れ
1. 本編URLを受け取る → `scripts/download.sh <URL>` で動画と字幕(SRT)を `input/` に取得
2. 字幕を読み、テーマごとに「いい場面」を選ぶ(数より質)。候補と見出し案3つをユーザーに出して選んでもらう
   - 字幕がない場合は `scripts/transcribe.py` で文字起こしする
3. 選ばれた区間を `scripts/make_short.sh` で縦型に変換 → `output/` に出力
4. 概要欄テキストを `output/<ファイル名>.txt` に作成
5. `log/shorts_log.md` に1行追記(必須)

## 方針(最優先)
- 本数より質。量産しない。1本ずつ「見た人が本編を見たくなる」ことを基準に作る
- 1つのテーマごとに、本編中のいい場面だけを選んでつなぐ(一部分の切り抜き1か所とは限らない)。つなぎは `scripts/concat_clips.sh`
- 目的は本編(メインチャンネル)への誘導。答えは全部見せず、続きが気になる形で終える

## 絶対にやらないこと(雑な仕事の禁止)
- 前後のシーンの映像が一瞬でも映り込んだまま渡さない。継ぎ目・冒頭・末尾に、別のシーンのコマが残ってはいけない
  - 文字起こしの秒数だけで切らない(ずれる)。必ず元動画のカット位置に合わせる(`scripts/find_cuts.py` → `concat_clips.sh` が自動で合わせる)
- 確認せずに渡さない。渡す前に、全本について次を実際に見て確かめる:
  1. `scripts/check_short.py` で「0.5秒未満だけ映るシーン」が無い
  2. 継ぎ目(つなぎ目)の前後、冒頭、末尾のコマを画像で見て、別シーンが混ざっていない
  3. 冒頭で話が唐突に始まっていない、末尾で文や単語が途中で切れていない(音を聞くか、字幕の区切りで確認)
- 単語・文の途中で切らない
- 文字起こしの誤りを、そのまま見出しや概要欄に使わない
- 確認できていないURL・事実を、確定として書かない(「要確認」と書く)
- 「直しました」と言う前に、直った結果を自分で見て確認する(見ないで言わない)
- 中身のない形容詞(強すぎる・ヤバい等)だけの見出しを作らない

## シーン選定の基準
- 冒頭3秒で引きがある(結論・問い・意外な主張から始まる)
- 1つのテーマで完結して理解でき、かつ「続きが知りたい」で終わる
- 具体例・数字・行動指針がある
- 40〜50秒(終了カード3秒を含めて50秒前後)。文の途中で切れない(字幕の区切りに合わせる)
- 誇張・断定が強すぎる表現は、見出しで和らげる案を出す
- ユダヤ人全体を一括りにする断定は避け、「ユダヤの教え」「ユダヤ商人の考え方」等の表現にする

## 見出しの作り方(ここが一番大事。センスで決めず、この型で詰める)
見出しは「誰に向けた動画か」と「見ると何が得られるか」が一目で分かること。
- 必ず入れる: ①誰向けか ②何が得られるか(知りたくなる問い)
- 型の例:
  - なぜ○○は××なのか?(問い) 例: なぜルフィは/最強チームを作る/天才なのか?
  - ○○したい方は必見(対象を明示) 例: 最強のチームを/作りたい方/必見
  - ○○の人がやっている△△(具体) 
- 作らない見出し: 「強すぎる」「ヤバい」「すごい」など中身のない形容詞だけのもの。何の話か、誰に向けたかが分からないもの
- 結論は見出しに書かない(答えは本編へ)。ただし問いは具体的に
- 3行以内。1行は8文字前後、最終行(キーフレーズ)は金の帯で強調
- 見出し案は3つ出して、ユーザーが選ぶ

## レイアウト(1080×1920, デザインB「黒×金」) ※YouTubeショートのUIを避ける
- 背景は黒(#0A0A0A)。上250pxと下420pxは、検索バー・タイトル・キャプション・ボタンで隠れるので文字を置かない
- 見出し(y 262〜): Zen Kaku Gothic New Black。白の行+最終行(キーフレーズ)は金グラデの帯に黒文字。中央そろえ、3行以内
- 動画(y 716〜1324): 元動画を横のまま1080×608、金縁付き
- CTA(y 1346〜1466): 金の丸ボタン「本編はコメント欄から →」を全編通して表示
- 終了カード(最後の3秒): 動画部分を「続きは / 本編は / コメント欄から →」に切り替え
- テロップ等は透過PNG(`scripts/make_assets.py`)。ffmpegでもPremiere Proでも同じ素材を使う。共通素材は `assets/`(README参照)
- フォントは `fonts/`(OFL)。見た目を変えるときは make_assets.py と、この欄を両方更新する

## 概要欄テンプレ
```
{見出し}

▶ 本編動画(この続きはこちら)
{本編URL}?t={開始秒}

#ユダヤ #ユダヤ人 #ビジネス #お金 #shorts
```
- 動画内で「コメント欄から」と案内しているので、固定コメントにも同じ本編リンクを貼る(概要欄と同じ文面でよい)
- 本編リンクは、切り抜き開始位置の秒数付き(youtu.be形式なら `https://youtu.be/<ID>?t=<秒>`)
- タイトル案は3つ出し、ユーザーが選ぶ

## 2重チェック(ユーザーに確認させない。自分で必ずやる)
- 1回目(自動): `python3 scripts/qa_check.py <開始> <終了>`。解像度・30fps・音声・長さ40〜53秒・見出し/金の帯・金縁・CTA帯・終了カード・一瞬映るシーン・ログ/概要欄・本編URLのタイトル一致(YouTubeで照合)・見出しの禁止語 をチェック。NGが1つでもあれば渡さない
- 2回目(目視): `output/qa/*.png`(冒頭・末尾・終了カードのコマ)を自分で見て、別シーンの混入・文の途中切れがないか確認。継ぎ目がある動画は継ぎ目の前後も見る
- 納品(`deliver.py`)は1回目のチェックに通らないと止まる。ZIP名・中身の名前・番号なし・本数も自動で確かめる
- 報告では「何をチェックしたか、何が見つかって、どう直したか」を書く

## 納品の仕方(クライアントに渡す形)
- 元動画ごとに分けて、ギガファイル便に1リンクずつアップロードする。`python3 scripts/deliver.py <開始番号> <終了番号>` で一括(保存期間30日)
- ZIPの名前は元動画のタイトル、中の動画ファイル名は内容(見出し)にする。番号はクライアントには意味がないので付けない(番号は社内管理用だけ)
- 1本だけの元動画もZIPにまとめる(形をそろえる)
- 納品リストは元動画ごとに区切り、「元動画タイトル / 元動画URL / ダウンロードリンク / その中の動画の見出し」を書く(番号は書かない)。ユーザーはこれを渡すだけ、クライアントはリンクから落とすだけにする
- 削除キーは社内用の別ファイルに残す(クライアント用リストには書かない)
- 渡し済みの番号は再送しない(01〜05は納品済み)

## ログ(log/shorts_log.md)
ショートを作るたびに、必ず表へ1行追記する。
列: 日付 / 本編タイトル / 本編URL / 切り抜き区間 / 見出し / 出力ファイル / 概要欄リンク(秒数付き) / 投稿済み
- 同じ本編の同じ区間を重複して作らないよう、作る前にログを確認する
- 投稿したと聞いたら「投稿済み」を✅にする

## 使うコマンド
```
scripts/download.sh <YouTube URL>
scripts/make_short.sh <input.mp4> <開始> <終了> <output.mp4> "<見出し1>" "<見出し2>" ["<見出し3>"]
scripts/concat_clips.sh <input.mp4> <output.mp4> "<開始秒> <終了秒>" "<開始秒> <終了秒>" ...   # 複数の名場面をつなぐ
# 例: scripts/make_short.sh input/abc123.mp4 00:03:12 00:04:00 output/abc123_0312.mp4 "なぜルフィは" "最強チームを作る" "天才なのか？"
```
必要: ffmpeg, yt-dlp, python3(pillow, faster-whisper)。Macは `./setup_mac.sh` で一括インストール

## 注意
- `input/` `output/` はgit管理しない
- 自分のチャンネルの動画のみを対象にする
- 場面選びは、前置き・雑談・作品のあらすじ説明を外し、冒頭からノウハウが始まる箇所だけにする(文字起こし全体を読んでから選ぶ)
